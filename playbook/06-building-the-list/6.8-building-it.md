# 6.8 Building It

> 🛠️ **This is how to build the list. Not a menu of options.**
>
> Source and resolve with LocalPipe, add the judgment enrichment in Clay or Claude Code, then verify, bucket and ship. Three steps, and the order is the whole trick.

## 🧱 The Stack

| Step | Tool | What it does |
| --- | --- | --- |
| **1. Source and resolve** | LocalPipe | Finds the businesses, resolves the owner, returns the addresses and the phone |
| **2. Judgment enrichment** | Clay or Claude Code | Answers the questions specific to your offer that no database can know |
| **3. Bucket and ship** | Your sequencer | Bucket assignment, suppression, one file per campaign |

## 1️⃣ Source and Resolve With LocalPipe

Start here, because this is the step everything else depends on and the step that is hardest to do well yourself.

Two ways in, and both are correct.

### 🖥️ The interface

Search by category and geography, filter on the record, export enriched contacts. Fastest route from nothing to a usable list, and the right default if you are running one or two markets.

### ⌨️ The API, driven from Claude Code

Better if you run several markets or want the sourcing to sit inside a repeatable workflow.

1. 📄 Download the API docs as markdown, plus the category CSV
2. 🤖 Drop both into Claude Code with your API key. The docs are written for an agent to read
3. 💬 One instruction: *build me a search and enrich engine I can drive in words*
4. ⏱️ Five to ten minutes, and that is the whole build

> 📌 **Repo note, not part of the original guide.** A copy of the API docs and the category CSV is kept in [`localpipe/api/`](../../localpipe/api/README.md), with the live download links.

**Two endpoints do the work.** Search batches locations and keywords per call, with exact category matching against the Maps taxonomy and filters for rating, review count, website presence and price level. Enrich returns owner name, owner direct email, general business email and phone, with title waterfalling and a fallback flag on the generic address.

**A worked example:** 200 plumbers in Austin with websites returned owner names on **74%**, verified owner emails on **24%**, business emails as a fallback on another **27%**, so **51% total verified email coverage**.

> 🎓 **Watch a walkthrough before your first build** rather than working it out from the docs. Both routes are covered in the training that comes with this guide.

## 2️⃣ Add the Judgment Enrichment

LocalPipe gives you who they are and how to reach them. It cannot know what matters for *your* offer.

That is the second layer, and it is where a list stops being a list and becomes a campaign:

- 🔍 Does this practice already list the services I complement?
- 🗣️ Do their reviews mention the problem I solve?
- 👤 Is the owner named anywhere on the site, in their own words?
- 📣 Are they running ads right now?
- 💼 Are they hiring, and for what?

Those are the signals from 5.4, and this is where you actually collect them.

### Two ways to run it

> 🧪 **Clay**
>
> The right default. Visual, no code, and built for exactly this: read a website, ask a question, score the answer, waterfall across providers.
>
> Best if you want something a team can maintain without a developer.

> ⌨️ **Claude Code**
>
> Better if you already built your sourcing there, or the enrichment is unusual enough that a visual tool fights you.
>
> Cheaper at volume, and it lives next to the rest of your workflow.

> 🎓 **Do not know Clay yet?**
>
> Do not try to learn it from this guide. Clay have built the training properly and it is free.
>
> [**Clay University**](https://www.clay.com/university) covers the fundamentals, waterfalls, AI research and outbound automation. Do Clay 101 first, then the Automated Outbound course.
>
> Come back here once you can run a waterfall and write a Claygent prompt.

### Three rules for this layer

- 🆓 **Use what came back free first.** Category, review count, website presence and opening hours are already on the record. Do not pay to infer something you were given
- 📐 **Look for a rule before you reach for AI.** If a formula can derive it, derive it. Free and deterministic beats paid and probabilistic
- 🚩 **Run a hallucination check column.** Flag any row that is blank, says N/A, or contains an apology, then spot-check those against the source. AI enrichment fails quietly

## 3️⃣ Bucket and Ship

The short step, and 6.7 has the detail.

- ✅ **No extra verification pass on LocalPipe exports.** They come triple verified, at sub 1% bounce. Verifying already-verified addresses costs money and removes nothing
- 🔬 **Verify anything you resolved yourself**, from a crawl, a filing or a guessed pattern. That is where bounces come from
- 🪣 **Assign each record to exactly one of the four buckets**
- 📁 **One file per bucket**, named consistently
- 🚫 **Suppression loaded** across every sending domain

## 💰 The Order That Saves Money

Whatever you build, run it in this sequence. Each paid step runs on a smaller set than the one before.

1. 🗺️ **Source the businesses.** Cheap
2. 🎚️ **Qualify and score on the record.** Free
3. 🗑️ **Drop the D tier.** Free
4. 👤 **Resolve owners.** Costs money
5. 🧠 **Judgment enrichment** on what survived. Costs money
6. 🪣 **Bucket and ship.** Free

Reverse any two of these and you are paying to enrich records you are about to discard. Section 6.7 shows what that costs in practice.

## 🔧 Yes, You Could Build the Resolution Layer Yourself

Briefly, for completeness, because it is a real option and the numbers are real.

Scrape Maps, crawl the site, search as a fallback, run an open-weight model on a rented GPU to read everything and name the owner, verify with a second pass, then run the email finders. Across a 10,000 business run that returns about **7,542 owner names**, which is roughly the same find rate you would buy.

What it costs: six or more hours to a working workflow, sources that change layout and break quietly, permanent maintenance, and per-operation finder charges either way.

For almost everybody reading this, that is the wrong trade. You are not in the data business, and the hours go further on the offer, the copy and the phone. Build it only if volume is high enough that per-find pricing genuinely hurts.

## ✅ Before You Move On

- Sourcing and owner resolution running through LocalPipe, by interface or API
- A judgment enrichment layer in Clay or Claude Code, answering questions specific to your offer
- Clay University bookmarked if you are new to it
- The credit-saving order applied, so paid steps run on the smallest set
- Bucketed and exported as one file per campaign, with nothing re-verified that arrived verified
